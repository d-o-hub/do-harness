# Heuristics
- **task done refuses until verify --record --task <id> records the named sensor beat**: workflow gate on task completion (from trace 1)
- **persistence commands failing with FutureDatabase means the release binary predates the state schema: rebuild (cargo build --release -p do-harness); doctor now flags binary/database migration skew before any command dies**: stale binary vs migrated agent_state.db (from trace 2)
- **decompose module when file nears 500 LOC (extract cli/catalog to stay under 450)**: 500 LOC ceiling; decompose at 450 per AGENTS.md. main.rs 462->331 via cli.rs, migrate.rs 452->392 via migrate_catalog.rs; check-loc green, clippy/test green (from trace 6)
- **extract migration catalog into separate module to reduce migrate.rs**: Embedded MIGRATIONS array bloats migrate.rs; move Migration+MIGRATIONS to migrate_catalog.rs (from trace 7)
- **adjacent guardian-proxy crate off-by-default, fail-closed, gates via ProxyMediator**: crates/guardian-proxy with ProxyConfig deny_unknown_fields, ProxyMediator::decide fail-closed, feature agt-governance, CI checks (from trace 9)
- **install the exact CI tool locally when a CI-only sensor fires**: cargo-deny missing locally masked the deps failure (license reject) that CI enforced; check-deps.sh now fails closed on CI=true without cargo-deny, mirroring check-audit.sh (from trace 11)
- **triage remote branches via merged list plus triple-dot diff-stat before deleting**: `git branch -r --merged main` plus `git diff --stat main...origin/<branch>` classifies merged/absorbed (empty diff, safe to delete) vs superseded/stale/unique (needs product review, never auto-delete) (from trace 12)
- **Concurrent SQLite writers retry lock/busy errors with backoff and re-read the chain tail inside the transaction**: SQLITE_BUSY and WAL snapshot conflicts surface under concurrent verify --record/task advance; retry the whole transactional unit, keep seq unique, and tolerate concurrent migrators (from trace 14)
- **Persisted structs that round-trip through files must own their strings; &'static str fields compile for construction but fail deserialization from non-'static buffers (E0597)**: Applies to evidence artifacts, chain payloads, and any serde struct that is both written to and read back from disk (from trace 15)
- **Node's --test flag takes files/globs, not bare directories, on Node 24: 'node --test test/' resolves as a module path and fails MODULE_NOT_FOUND; use 'node --test test/*.test.mjs'**: Applies when wiring JavaScript test suites into scripts or CI for the DSH bundle or any Node package (from trace 16)
- **Cordis/DSH contains plugin apply() errors: a failed mount keeps the host process running with no console output, so verify registration against a minimal real context (systemPrompt -> dsh-tools -> dsh-subprocess-local -> plugin) and read ctx.tools.schemas()/execute()**: Applies when validating DSH/Cordis bundle integrations where a booted process staying up does not prove the plugin mounted (from trace 17)
- **extract the inline #[cfg(test)] module to a sibling <module>_tests.rs declared in the parent mod.rs when the LOC sensor fires**: applies when a source file crosses the 500-line ceiling because of fixture tests, keeping production code under the cap; `do-harness split <file>` performs this extraction mechanically (it emits the `#[path = …] mod …;` declaration and moves the bodies) (from trace 19)
- **after removing an adapter or feature surface, sweep every public claim that named it (README, docs links, epics, skill heuristics, completions/man) and refresh evidence artifacts in the same slice**: truth decay after refactors that delete public surface: stale docs and stale evidence both masquerade as green (from trace 20)
- **tool-unavailable sensor paths must emit a SKIP: marker that verify surfaces as WARN and evidence records as non-pass, never a silent exit-0 pass**: supply-chain and lint sensors whose tools may be absent; keeps the local gate usable while strict/status stay honest (from trace 21)
- **any file under templates/skills must exist for every path its SKILL.md references, and embedded scaffolds must write those files; extend the sync sensor to assert referenced-path existence**: template drift when canonical skills gain references that the scaffold subset never copies (from trace 22)
- **in a shallow clone, do not trust triple-dot diffs or main..branch counts; compare branch tip trees to the matching main commit and confirm remote refs with git ls-remote before declaring a branch prunable**: branch triage and prune decisions in shallow or grafted clones (from trace 23)
- **when wiring rmcp ingress, build ServerConfig via Default plus field assignment (it is non_exhaustive), mount StreamableHttpService with nest_service while exact routes keep precedence, and keep the SDK behind an optional feature so the default MSRV stays put**: official MCP SDK ingress wiring in a proxy crate with legacy routes and a lower workspace MSRV (from trace 25)
- **when a test file crosses the LOC ceiling, move a themed group of tests into a child module file declared as mod <theme>; in async tests hold std Mutex guards in a braced scope rather than drop(), because await_holding_lock does not honor explicit drop**: test-file LOC decomposition and async locking lints in Rust (from trace 28)
- **when deprecating an HTTP route, make it executable: always send Deprecation: true and emit the successor Link only when the successor is actually served; mirror the architecture decision into plans/invariants.json and seed libSQL in the same slice**: route deprecation and architectural decision records that must stay verifiable (from trace 29)
- **a deprecated route cannot be removed while its successor is feature-gated off: promotion of the successor and retirement of the incumbent are one decision, so price MSRV and dependency costs before flipping defaults**: promotion decisions where a deprecated surface is coupled to a feature-gated successor (from trace 30)
- **install the optional tools the generated contract probes before any CI dogfood of init (cargo-deny, cargo-audit), because the deps/audit sensors fail closed when CI=true**: release or matrix jobs that run init on a fresh workspace without the full toolchain (from trace 33)
- **a crate that embeds files outside its directory cannot be published: symlink them under the crate (cargo dereferences symlinks into the tarball) and keep template manifests out of nested-package directories**: cargo package/publish of a workspace crate that include_str!s shared docs, catalogs, or scaffolds (from trace 34)
- **ship a prebuilt native binary to npm as per-platform packages gated by os/cpu, resolved from the meta package's pinned optionalDependencies, and validate assembly in CI with npm publish --dry-run (no token needed)**: zero-install npx wrappers around a compiled CLI (from trace 35)
- **keep PR titles lowercase-conventional from creation: squash merges immortalize the title on main HEAD, where the commitlint sensor (COUNT=1, --no-merges) lints it and one uppercase word fails every downstream PR verify until a forward fix lands (direct push justified when the PR path cannot go green)**: squash-title hygiene and main-HEAD repair (from trace 36)
- **on windows-latest every run: step using bash syntax needs explicit shell: bash (pwsh is default), including release-matrix jobs that only reach windows at tag time; scope the windows CI job to the distribution proof (build + Git Bash dogfood + npm) while the full unit suite is not Windows-green (walkthrough shebangs, hook exit codes/path resolution tracked under the platform issue)**: Windows CI portability (from trace 36)
- **AGT contributor-check scores a repo collaborator with push access but no org membership as MEDIUM on profile, has no allowlist input, and risk-threshold only tunes comments (not the risk output): mitigate with threshold HIGH plus fail-closed only on HIGH/unknown, and file the scoring/allowlist asks upstream (draft needs a token with upstream issue scope)**: third-party reputation-gate false positives (from trace 37)
- **scaffold copies drift silently: templates/scripts mirrors of integration sources have no sync sensor, and no node --check covers scaffolded .mjs wrappers — add a sync assertion plus a parse lint before shipping new packs**: template duplication and wrapper coverage (from trace 37)
- **diagnostics emitted while a --format json command runs must go to stderr; a single stdout println corrupts the one-JSON-object contract**: verify --bless messages and verdict lines; any CLI path that prints during JSON mode (from trace 36)
- **a ratchet that must hold in CI belongs in a committed file (plans/baselines.json), not only local libSQL; hash its bytes into the policy fingerprint so a bless invalidates stale evidence**: findings ratchets, eval floors, any gate that must be identical across clones and CI (from trace 36)
- **adding a new db repo module requires registering it in schema_usage PROD_SOURCES or the dead-column guard reports its columns as unwritten**: new crates/db/src/repo_*.rs writers (from trace 36)
- **schema bumps in deny_unknown_fields structs add defaulted fields, widen the status acceptance range, extend the chain-seal payload, and update every dogfood version assertion; pre-fingerprint schemas stay legacy**: evidence schema versioning and additive compatibility (from trace 40)
- **an intermittent ETXTBSY ("Text file busy" / os error 26, ErrorKind::ExecutableFileBusy) on exec means a fork/exec race, not a broken script: a forked child holds inherited write-descriptors until its own execve completes, so exec of a just-written file fails while another thread is mid-write — retry via shell::retry_executable_busy and treat a silent fallback as the symptom**: any path that execs a script this process just wrote (write + chmod + spawn): skill walkthroughs, the semantic selector, hook runners; it surfaces as an intermittent test flake (~1/8) or a silently degraded code path (from trace 6)
- **run `do-harness loc` before editing a file that is already near the ceiling, and `do-harness split <file>` when the LOC sensor fires on a file with an extractable #[cfg(test)] module or one oversized top-level item**: feedforward LOC management: `loc --warn` prints total/code/test per file without running the sensor, `split` extracts the module (or the largest item that is itself under the ceiling) and prints the plan first; `split` refuses rather than emitting code it cannot make compile when macro_rules!/include!/non-test cfg shapes are present (from trace 41)
- **a lexical path check plus is_dir()/read_dir() follows symlinks: canonicalize the root and each managed directory and require containment before hashing a tree, and never render entry paths with to_string_lossy because distinct non-UTF-8 names collapse onto one replacement character and make the provenance digest ambiguous**: cross-repo provenance digests, or any code that hashes a manifest-declared directory tree; the same review also showed that accepting an abbreviated commit pin (7 hex) leaves a provenance anchor ambiguous across repositories and time (from trace 1, session skills-drift-hardening)
- **a sensor that parses tool output on stdout can report a phantom finding forever: check the parser against the mode actually used (`cargo llvm-cov nextest --lcov` prints no `TOTAL` table, so the harness parsed nothing and shipped `FINDINGS: 1` on every run until the count was derived from the report's own LH/LF totals)**: any sensor whose verdict is computed from captured command output, especially coverage or benchmark wrappers whose flags change the printed summary (occurred in the coverage sensor, which sat quarantined at `attempt_count=3` because of it)
- **a test that spawns a nested build must strip the launcher's toolchain state: an inherited RUSTC_WRAPPER (cargo-llvm-cov), RUSTFLAGS, CARGO_TARGET_DIR or LLVM_PROFILE_FILE makes the nested `cargo llvm-cov nextest` re-enter the running session and die with `Resource temporarily unavailable (os error 11)`, so sandbox assertions flip only under instrumentation and never under `cargo test` — and instrumented children drop `default_*.profraw` into their working directory**: sandbox/dogfood tests that run cargo or the built binary under a coverage or wrapper session (from PR #185 triage)
- **a toolchain pin file (`rust-toolchain.toml`) silently overrides the toolchain a CI job installs, so a "check on MSRV" step that only runs `cargo check` tests the pinned channel and cannot detect its target regression class (MSRV-only breaks; ordinary compile errors would still fail it) — measured here: the job reported PASS while `cargo +1.85 check --workspace --locked` failed with five let-chains in `binary.rs`, `hooks.rs`, and `status/locate.rs`**: select the version explicitly (`RUSTUP_TOOLCHAIN: <msrv>` or `cargo +<msrv>`), prefer `--all-targets` so test code is covered too, and run the suite rather than only a check when the claim is that the package is *verified* on its MSRV — the Cargo Book's `Verified` expectation is "automated testing" on the supported version, which a type check is not. State the feature scope: `cargo test --workspace` covers default features only, so verify the MSRV-clean optional features explicitly and record (never silently drop) any feature whose dependency needs a newer compiler; a gate that cannot detect the regressions it targets is worse than no gate, because it certifies a false `rust-version` claim (from the MSRV slice)
- **a CI job that dogfoods `init`/`verify` must install the tools the scaffolded pack's sensors probe for: `init` emits (or withholds) sensors by probing for their tools, so a minimal-profile toolchain silently changes the pack — missing `rustfmt`/`clippy` components and `cargo-nextest` dropped `fmt`, `clippy`, and `test` from the report and the presence assertions failed, in the same configuration that is green locally**: any job running the test suite on a toolchain installed with `profile: minimal` or on a fresh runner without the pack's tools (from the MSRV slice)
- **Workload-aware Tokio guidance (template #336)**: keep short bounded CPU (<10-100µs) on async worker threads rather than cargo-culting spawn_blocking offloads; reserve spawn_blocking/pools for genuinely blocking disk/FFI or sustained heavy CPU (>1ms); flag unbounded spawn fan-out, lock-across-.await, and repeatedly-ready loops during review (workload-aware Tokio guidance)
- **a release preflight must install every tool the gated sensor set runs: the tag preflight listed cargo-deny, cargo-audit, and shellcheck while the `test` sensor runs `cargo nextest`, so the one missing tool failed `verify --strict` (`FAIL test — error: no such command: nextest`) and every publish job skipped (measured on the v0.1.2 tag)**: any CI job that runs a sensor set, especially a tag-gated release preflight whose tool list is maintained separately from the workflow that normally runs those sensors (from the v0.1.2 release cycle)
- **a tag-triggered workflow runs the workflow file from the tagged commit, so a `release.yml` fix cannot be validated by re-running or re-pushing the existing tag — delete the tag (and any release already created from it) and re-create it on the fixed commit; `gh run rerun` replays the old file identically** *(refined by the tagged-dispatch heuristic above: a `-f tag=` dispatch runs the fixed file against the tagged commit, so re-cutting the tag is only for when the version itself must be replaced)*: release/preflight fixes whose correctness is only observable in the tag run (from the v0.1.2 release cycle)
- **`include_str!` / `include_bytes!` must not escape the crate root: `cargo package` refuses paths outside the package root, so the crate compiles and tests locally yet cannot build from its own tarball, failing `cargo publish` with `error: couldn't read src/../../../.config/nextest.toml` — symlink the external file into an in-crate `assets/` directory, which `cargo package` dereferences (measured: two crates published, the CLI failed eight attempts)**: any crate that embeds repository-level files, guarded by an include-path test that fails when a literal resolves outside the crate (from the v0.1.2 release cycle)
- **npm trusted-publisher configurations created after 2026-09-03 default to allowing `npm stage publish` only: a workflow that runs `npm publish` gets `403 … OIDC permission denied for this action` until the connection is granted direct publishing (`npm trust github <pkg> --file <wf.yml> --repo <owner/repo> --allow-publish`, or the package's Trusted publishing settings), and the grant is per package name and needs an interactive 2FA challenge**: first release through a newly configured trusted publisher after that date, where the failure looks like an auth problem but is a missing permission on the action (from the v0.1.2 release cycle)
- **a sensor that clears shared state under `set -e` can abort its own retry: the audit sensor ran `rm -rf "$CARGO_HOME/advisory-db"` in its recovery branch, so on the Windows runner — where parallel dogfood sandboxes share that database and one process's cleanup collides with a sibling's files — `rm: cannot remove …: Permission denied` killed the sensor before the retry the branch existed to perform, and the dogfood assertion failed for a reason unrelated to the code under test (occurred twice, then fixed)**: retry before touching shared state, and make the cleanup best effort with `|| true` so the retry always runs; a PATH-faked tool pins the retry, the bound, and the cleanup case (from the v0.1.2 release cycle)
- **a guard test that accuses the whole schema may be reading nothing: `env!("CARGO_MANIFEST_DIR")` is baked in at compile time, and cargo reuses a unit whose Rust inputs are unchanged even when it was built in a different checkout that shared this `target/`, so `crates/db/tests/schema_usage.rs` read no `PROD_SOURCES` files and reported every column as unwritten while the same test passed by hand in the same tree — grep `target/debug/deps/*.d` for source paths outside the checkout (`grep -lE '/tmp/(rel-verify|hyg-pr|imm-pr)/'`) and delete those units (binary plus `.d`) before debugging the code; `strings <binary> | grep -oE '/(tmp|home)[^ ]*/crates/db'` names the baked manifest path that confirms it**: any hermetic test that reads repo sources relative to `CARGO_MANIFEST_DIR`, especially after pruning a worktree whose `target` was symlinked into the main one; the read now fails loudly with the offending path instead of an empty concatenation (from trace 9, session repo-sync-foreign-build-artifact)
- **almost every recorded architecture invariant can retire without a sensor noticing: `plans/invariants.json` is guarded only structurally (`yamllint` parses `plans/*.json`) plus a single name grep, so measured on detached worktrees at `main`, deleting the immutable-release entry (45 → 44 entries, still valid JSON) left `check-yamllint`, `check-promotion-decisions`, and `check-loc` at exit 0, while replacing the one `chore-agt-promotion` token — the only string `check-promotions` greps this file for by name — failed that gate with exit 1 and left yamllint green; a count ratchet would miss the common shape anyway, because replacing one entry with another leaves the array length identical**: review any diff that touches `plans/invariants.json` or the policy docs it cites as a possible silent retirement, and ask "who deleted this entry, and was it retired on purpose?" in review rather than expecting a sensor to (from trace 10, session invariant-removal-gap)
- **a revert hidden in a PR is told apart from a merge artifact by reading parents, not by reading the diff: `git rev-list --parents -1 <sha>` plus `git grep -c <token> <sha> -- <path>` at each step shows whether the merge itself dropped the content or an ordinary single-parent commit did it afterwards — measured on an open PR, the merge `13f6747` still carried the entry (count 1) while the following commit `7328cdc` (one parent) deleted it with a real diff, so the change was authored, not a conflict resolution, and the branch must not be "fixed" by restoring the other side without confirming intent**: triaging a PR whose diff removes content that landed on main after it branched (merge commits in a squash-merged repo make the artifact hypothesis tempting) (from trace 10, session invariant-removal-gap)
- **a sensor that passes alone but fails under `cargo run … verify` may inherit the harness launcher crate identity: cargo-machete 0.9.1 treats `CARGO` plus absent `CARGO_PKG_NAME` as Cargo subcommand dispatch, so inherited `CARGO_PKG_NAME` makes it scan a directory literally named `machete`; strip launcher `CARGO_PKG_*`, manifest, and build-output identity variables at the sensor spawn boundary, while preserving `CARGO`, toolchain selection, and `DO_HARNESS_*` contract variables**: diagnose child-env differences before blaming a sensor script; reproduced as `FAIL machete` under `cargo run` and `PASS machete` after runner sanitation (sensor env leak incident)
- **a published binary-only crate breaks `cargo semver-checks check-release`: `do-harness` exits 101 with `error: no library targets found in package do-harness` — the crates.io v0.1.2 baseline has no lib target to rustdoc, so the comparison fails for a reason no API change caused; represent that exact baseline with a committed empty-lib crate passed to `--baseline-root`, gate the fallback on the version parsed from the tool's own output, and otherwise pass through the original exit status**: preflight of a crate that ships a binary and no library; materialize the fixture outside the checkout (`mktemp -d`), since a second manifest for the same name under the workspace root makes `-p` ambiguous (`defined by in multiple manifests within the root path`) — measured: empty baseline 196 pass, synthetic v0.1.3 exits 101 (from trace 11)
- **no shell `grep` spelling counts NUL bytes: bash cannot put NUL in an argument, so `grep -c $'\x00' <file>` degenerates to an empty pattern that matches every line (2 printed for a one-line probe holding exactly one NUL, hundreds for two files holding none), and a NUL inside a `-P` pattern ends the pattern string (`LC_ALL=C grep -c -P '\x00'` printed 0 on that same probe) — count bytes instead (`python3 -c 'print(open(p,"rb").read().count(b"\x00"))'`)**: diagnosing a file that suddenly fails to parse (`jq`: `Unrecognized token '\u0000'`); recover by restoring from git, re-applying each change as a plain string replacement, and re-counting the bytes (from trace 12)
- **generated shell scripts and repo tooling must clear the repository-local git variables git publishes (git rev-parse --local-env-vars), not a hand-kept subset: hook-exported GIT_DIR/GIT_WORK_TREE and caller-set GIT_COMMON_DIR/GIT_SHALLOW_FILE/GIT_GRAFT_FILE redirect or rewrite which repository and history git reads**: any script, hook, or fixture that invokes git with --root/cwd semantics different from the caller's repository (githooks(5) documents unset $(git rev-parse --local-env-vars) for exactly this) (from trace 1)
- **a gating sensor that can be turned green by environment variables is not a gate: assert on content (the specific violation must still be reported), not on the exit code, and clear the steering variables first**: false-green vectors where an inherited variable hides the finding (GIT_SHALLOW_FILE hid the bad commit -> rc=0) or converts the run into an unrelated error (GIT_COMMON_DIR -> fatal: bad object HEAD); also applies to any lint/gate whose exit code can move for reasons other than the finding (from trace 2)
- **never version the local state database: commit the contract instead (schema migrations, policy/baseline JSON, text snapshots/export) and keep .do-harness/ ignored**: repository hygiene for local telemetry/state stores: a live SQLite file has no diff or merge, carries -wal/-shm sidecars, and a copy taken while a transaction is active can be corrupt (SQLite 'How To Corrupt An SQLite Database File' 1.2); hosting guidance says Git is not designed to handle large SQL files (from trace 3)
- **ground best-practice claims in the current official document, fetched at answer time and quoted with its URL, and state the version verified against**: answering 'what is best practice' questions or writing docs that cite one: search snippets paraphrase and drop the normative sentence, and memory drifts across releases (from trace 4)
- **a static musl binary can crash at teardown on a bug that glibc only reports under valgrind: freed-heap reads stay mapped under glibc (silent double free) but musl returns pages to the OS, so a second `sqlite3_close_v2`/`sqlite3Close` on the freed handle faults with SIGSEGV whose faulting address sits in an unmapped heap gap — and whether musl actually unmaps depends on allocation history, so the crash flips with argv length, input-file formatting, or prior commands and looks irreproducible (measured: `do-harness seed` exit 139 only on the installed static-pie binary, never under fresh glibc builds; `--root $PWD` masked it, compact JSON unmasked it)**: any SIGSEGV inside sqlite3/libsql close paths, `valgrind` double-free reports, or crash/no-crash splits between glibc and musl builds of the same commit (from trace 1, session seed-segv-112; upstream tursodatabase/libsql#2251)
- **the conservative sensor input identity is every index or untracked-non-ignored path, so a sensor that writes generated files back into the repository invalidates its own run unless the pack ignores them — and a scaffolded repository is the first place that bites (observed: plain `init` + `verify` exited 1 with `evidence invalidated during run (inputs_changed_during_run)` while `All sensors passed`, because the generated `.gitignore` lacked `/target` and `/lcov.info` and the coverage sensor wrote `target/llvm-cov-target/**` plus `lcov.info`)**: when adding a sensor or a language pack, add its generated paths to that pack's `.gitignore` entries (`init.rs` language-specific set) or declare them under the sensor's `artifacts`; gitignored paths never enter the digest, so `lcov.info`, `.do-harness/` and `target/` are free (from PR #294 triage)
- **a fixture for a code path that branches on repository presence must itself be a repository: identity/reuse logic returns `None` digests outside git (unreadable `git ls-files`), so a plain tempdir fixture exercises the no-git branch and asserts on behavior the real path never runs (observed: bless fixtures without `git init` stayed green while `verify --record --bless` self-invalidated with exit 1 in every repository; the fix's regression test needed a real `git init` fixture)**: for every such fixture, ask whether it would fail if the behavior under test regressed on the other branch, and add `git init` plus an initial commit when the answer is yes (from PR #294 triage)
- **a preview mode that short-circuits before the validations lies about the operation: share one gate between the preview and the real call, or the dry run reports success for transitions execution refuses (observed: `task done 1 --dry-run` printed "would mark task 1 done" while the real call errors with "has no method; cannot mark done"; `advance`/`fail`/`remove` had the same gap, and the fix split each transition into a shared gate plus a mutation with `preview_*` twins)**: Kubernetes documents the target shape for dry-run — the request is evaluated "through the typical request stages (admission chain, validation, merge conflicts) up until persisting objects to storage", "Authorization for dry-run and non-dry-run requests is identical", and a stage that would have side effects makes the request fail "rather than risk an unwanted side effect" (Kubernetes API Concepts, `#dry-run`, v1.37 docs, fetched 2026-10-12); the same page adds the boundary: "It is important not to rely upon the values of these fields set by a dry-run request" for generated values, and Terraform's plan reference draws it for the execution side — a speculative plan is "a description of the effect of the plan but without any intent to actually apply it", and because the target "might" have changed since, "you should always re-check the final non-speculative plan before applying" (terraform plan command reference, fetched 2026-10-12). So: pin parity with a regression test asserting the preview and the real call produce the *same* error text, keep previews write-free (pointer and append-only log untouched), and re-validate the head at execution (the `--match-head-commit` analogue of applying a saved plan) (from PR #301)
- **when `CARGO_TARGET_DIR` points outside the repository (a shared target dir), `./target/debug/<bin>` is a stale artifact and hand-testing it validates older code than the tree you just edited (observed: two dry-run checks "failed" against a binary from the previous day while the rebuilt one sat in the shared target dir; the pre-commit hook resolved its binary from PATH for the same reason)**: Cargo puts "all generated artifacts" at `CARGO_TARGET_DIR`, "relative to the current working directory", overridable via `build.target-dir` (The Cargo Book, Environment Variables, fetched 2026-10-12); locate the real output with `cargo metadata --format-version 1 --no-deps | jq -r .target_directory`, or run `cargo run -p <crate> -- <args>`, and prefer a test that drives `commands::<entry>` in-process over a shell check of a checked-out binary (from PR #301)
- **a full local `verify` at uncapped cargo parallelism can OOM a dev machine: the pre-push hook's check/clippy/nextest fan out to every core, `do-harness` invoked the OOM killer on a 14GB host and the kernel shot `opencode` twice plus terminal processes (measured 2026-10-14, 27 oom-kill lines), so export `CARGO_BUILD_JOBS=2` and `CARGO_INCREMENTAL=0` (the CI setting in `verify.yml`) before any local verify or push, shed background load first, and never stack full-verify retries — each retry re-runs the whole suite from zero (from PR #310 triage)
- **a green sensor that executed zero checks is a failed gate, not evidence: `cargo test --doc --workspace` passed with `0 tests run` because no public item carried a doc example, so the doctest sensor proved nothing — add a real doc-test (`chain_hash` determinism, 64-char length, and prev-sensitivity on `do-harness-types`) and treat any `0 run` sensor output as RED in review**: any gating sensor whose pass can be vacuous: test counts, empty suites, or skipped tools without `SKIP:` markers (from the doctest-zero incident, 2026-10-15)
- **a fixture or example that shells out to a POSIX-only script must declare the hosts it can run on, and the checker must map each host to a declared name and print the skip: on a Windows runner an unqualified `bash` resolves to the WSL launcher (System32), which exits 1 with "Windows Subsystem for Linux has no installed distributions" before the script's own `SKIP:` branch can run (measured: docs-examples `installer_local_artifact` failed the windows verify job; fixed with a validated `platforms` key plus a printed skip)**: any CI matrix that executes documented examples, scripts, or fixtures on more than one OS (from PR #336 CI triage)
- **the local toolchain compiles one target only: linux `cargo clippy --workspace --all-targets` and `cargo test` cannot see warnings in `cfg(windows)` code, so the windows CI job is the only cross-platform compiler gate — when touching platform-gated code run `cargo clippy --workspace --all-targets --target x86_64-pc-windows-msvc` (after `rustup target add`) or expect windows-only failures; toolchain skew is separately pinned by `rust-toolchain.toml`**: any change touching `#[cfg(unix)]`/`#[cfg(windows)]` paths or OS-specific test helpers (from PR #336 triage)
- **git exports its repository view to every hook (`githooks(5)`; `git rev-parse --local-env-vars`), and in a linked worktree that is an absolute `GIT_DIR` into the shared gitdir: leaving it in place makes the hook's children — including tests asserting "not inside a git repository" — resolve the hook's repository, so the generated verify-hook prologue clears the same `changes::GIT_VIEW_ENV` set the generated scripts clear (measured: a push from a linked worktree failed `exit_classification::doctor_without_a_git_repository_is_a_usage_error`)**: managed git hooks, hook-spawned tools, and sandbox tests that create tmpdir "not a repository" fixtures (from PR #336 triage)
- **an auxiliary worktree nested inside the primary checkout breaks cargo's workspace-upward resolution for excluded packages: `cargo fmt --all` fails with "current package believes it's in a workspace when it's not" while resolving the parent manifest, and the package-contract check's `cargo package --manifest-path vendor/libsql/Cargo.toml` fails identically, even though metadata/build/check at the worktree root still work — place verification worktrees in a sibling directory outside the primary checkout**: `git worktree add` under `.worktrees/`, any repo with `[workspace] exclude` entries (from PR #336 verification)

- **a pre-1.0 bump policy belongs to the ecosystem's release tooling, not to intuition: `next_version` (the crate release-plz uses) takes a breaking change as the *minor* at `0.x` and a feature as a *patch*, because `0.(x+1).0` is how a breaking change is signalled while the API is unstable — a feature-driven minor makes breaking changes invisible — and SemVer §4 ("Major version zero (0.y.z) is for initial development. - **a release pipeline fix can be applied to an already-pushed tag without moving it: give the tag workflow a `tag` dispatch input and run `gh workflow run <wf> -f tag=vX.Y.Z`, because a dispatch executes the *dispatching ref's* workflow file against the tagged commit — the tag never moves, and every publish step must be idempotent (crates.io and npm skip a version they already hold; an existing GitHub Release has its assets replaced)**: this supersedes the delete-and-re-create-the-tag remedy for the workflow-file case; the underlying tag-run rule is unchanged (`gh run rerun` still replays the old file), and the dispatch also works around `GITHUB_TOKEN`-created events starting no runs, since `workflow_dispatch` is the documented exception (from trace 42, session auto-release)

- **an atomic write built from `mktemp` + `mv` silently rewrites the target's mode: `mktemp` creates its file 0600, so `sed > tmp; mv tmp target` leaves a 0644 manifest owner-only (measured — `Cargo.toml` and the npm manifests went 644 → 600 after one release bump, invisible to git because git tracks only the executable bit) — capture the mode before the write (`stat -c '%a'` on GNU, `stat -f '%Lp'` on BSD/macOS) and `chmod` the temp before the move, then pin it with an assertion that fails when the restore is removed**: any write-through-temp helper that replaces a *tracked* file rather than a file inside a scratch directory (from trace 42, session auto-release)
- **a `concurrency.group` keyed to the triggering ref does not serialize a dispatch of the same release: `github.ref` is `refs/tags/vX.Y.Z` on a tag push but the default branch on a tagged `workflow_dispatch`, so the two runs that reconcile one GitHub Release land in different groups and race — key the group to the *effective* release tag (`release-${{ inputs.tag || github.ref_name }}`) instead**: any workflow that both triggers on a ref and is re-runnable by dispatch to act on the same artifact (from trace 42, session auto-release)
