# Heuristics
- **task done refuses until verify --record --task <id> records the named sensor beat**: workflow gate on task completion (from trace 1)
- **persistence commands failing with FutureDatabase means the release binary predates the state schema: rebuild (cargo build --release -p do-harness); doctor now flags binary/database migration skew before any command dies**: stale binary vs migrated agent_state.db (from trace 2)
- **decompose module when file nears 500 LOC (extract cli/catalog to stay under 450)**: 500 LOC ceiling; decompose at 450 per AGENTS.md. main.rs 462->331 via cli.rs, migrate.rs 452->392 via migrate_catalog.rs; check-loc green, clippy/test green (from trace 6)
- **extract migration catalog into separate module to reduce migrate.rs**: Embedded MIGRATIONS array bloats migrate.rs; move Migration+MIGRATIONS to migrate_catalog.rs (from trace 7)
- **adjacent guardian-proxy crate off-by-default, fail-closed, gates via ProxyMediator**: crates/guardian-proxy with ProxyConfig deny_unknown_fields, ProxyMediator::decide fail-closed, feature agt-governance, CI checks (from trace 9)
- **install the exact CI tool locally when a CI-only sensor fires**: cargo-deny missing locally masked the deps failure (license reject) that CI enforced; check-deps.sh now fails closed on CI=true without cargo-deny, mirroring check-audit.sh (from trace 11)
- **triage remote branches via merged list plus triple-dot diff-stat before deleting**: `git branch -r --merged main` plus `git diff --stat main...origin/<branch>` classifies merged/absorbed (empty diff, safe to delete) vs superseded/stale/unique (needs product review, never auto-delete) (from trace 12)
- **Concurrent SQLite writers retry lock/busy errors with backoff and re-read the chain tail inside the transaction**: SQLITE_BUSY and WAL snapshot conflicts surface under concurrent verify --record/task advance; retry the whole transactional unit, keep seq unique, and tolerate concurrent migrators (from trace 14)
- **Persisted structs that round-trip through files must own their strings; &'static str fields compile for construction but fail deserialization from non-'static buffers (E0597)**: Applies to evidence artifacts, chain payloads, and any serde struct that is both written to and read back from disk (from trace 15)
- **Node's --test flag takes files/globs, not bare directories, on Node 24: 'node --test test/' resolves as a module path and fails MODULE_NOT_FOUND; use 'node --test test/*.test.mjs'**: Applies when wiring JavaScript test suites into scripts or CI for the DSH bundle or any Node package (from trace 16)
- **Cordis/DSH contains plugin apply() errors: a failed mount keeps the host process running with no console output, so verify registration against a minimal real context (systemPrompt -> dsh-tools -> dsh-subprocess-local -> plugin) and read ctx.tools.schemas()/execute()**: Applies when validating DSH/Cordis bundle integrations where a booted process staying up does not prove the plugin mounted (from trace 17)
- **extract the inline #[cfg(test)] module to a sibling <module>_tests.rs declared in the parent mod.rs when the LOC sensor fires**: applies when a source file crosses the 500-line ceiling because of fixture tests, keeping production code under the cap; `do-harness split <file>` performs this extraction mechanically (it emits the `#[path = …] mod …;` declaration and moves the bodies) (from trace 19)
- **after removing an adapter or feature surface, sweep every public claim that named it (README, docs links, epics, skill heuristics, completions/man) and refresh evidence artifacts in the same slice**: truth decay after refactors that delete public surface: stale docs and stale evidence both masquerade as green (from trace 20)
- **tool-unavailable sensor paths must emit a SKIP: marker that verify surfaces as WARN and evidence records as non-pass, never a silent exit-0 pass**: supply-chain and lint sensors whose tools may be absent; keeps the local gate usable while strict/status stay honest (from trace 21)
- **any file under templates/skills must exist for every path its SKILL.md references, and embedded scaffolds must write those files; extend the sync sensor to assert referenced-path existence**: template drift when canonical skills gain references that the scaffold subset never copies (from trace 22)
- **in a shallow clone, do not trust triple-dot diffs or main..branch counts; compare branch tip trees to the matching main commit and confirm remote refs with git ls-remote before declaring a branch prunable**: branch triage and prune decisions in shallow or grafted clones (from trace 23)
- **when wiring rmcp ingress, build ServerInfo via Default plus field assignment (it is non_exhaustive), mount StreamableHttpService with nest_service while exact routes keep precedence, and keep the SDK behind an optional feature so the default MSRV stays put**: official MCP SDK ingress wiring in a proxy crate with legacy routes and a lower workspace MSRV (from trace 25)
- **when a test file crosses the LOC ceiling, move a themed group of tests into a child module file declared as mod <theme>; in async tests hold std Mutex guards in a braced scope rather than drop(), because await_holding_lock does not honor explicit drop**: test-file LOC decomposition and async locking lints in Rust (from trace 28)
- **when deprecating an HTTP route, make it executable: always send Deprecation: true and emit the successor Link only when the successor is actually served; mirror the architecture decision into plans/invariants.json and seed libSQL in the same slice**: route deprecation and architectural decision records that must stay verifiable (from trace 29)
- **a deprecated route cannot be removed while its successor is feature-gated off: promotion of the successor and retirement of the incumbent are one decision, so price MSRV and dependency costs before flipping defaults**: promotion decisions where a deprecated surface is coupled to a feature-gated successor (from trace 30)
- **install the optional tools the generated contract probes before any CI dogfood of init (cargo-deny, cargo-audit), because the deps/audit sensors fail closed when CI=true**: release or matrix jobs that run init on a fresh workspace without the full toolchain (from trace 33)
- **a crate that embeds files outside its directory cannot be published: symlink them under the crate (cargo dereferences symlinks into the tarball) and keep template manifests out of nested-package directories**: cargo package/publish of a workspace crate that include_str!s shared docs, catalogs, or scaffolds (from trace 34)
- **ship a prebuilt native binary to npm as per-platform packages gated by os/cpu, resolved from the meta package's pinned optionalDependencies, and validate assembly in CI with npm publish --dry-run (no token needed)**: zero-install npx wrappers around a compiled CLI (from trace 35)
- **keep PR titles lowercase-conventional from creation: squash merges immortalize the title on main HEAD, where the commitlint sensor (COUNT=1, --no-merges) lints it and one uppercase word fails every downstream PR verify until a forward fix lands (direct push justified when the PR path cannot go green)**: squash-title hygiene and main-HEAD repair (from trace 36)
- **on windows-latest every run: step using bash syntax needs explicit shell: bash (pwsh is default), including release-matrix jobs that only reach windows at tag time; scope the windows CI job to the distribution proof (build + Git Bash dogfood + npm) while the full unit suite is not Windows-green (walkthrough shebangs, hook exit codes/path resolution tracked under the platform issue)**: Windows CI portability (from trace 36)
- **AGT contributor-check scores a repo collaborator with push access but no org membership as MEDIUM on profile, has no allowlist input, and risk-threshold only tunes comments (not the risk output): mitigate with threshold HIGH plus fail-closed only on HIGH/unknown, and file the scoring/allowlist asks upstream (draft needs a token with upstream issue scope)**: third-party reputation-gate false positives (from trace 37)
- **scaffold copies drift silently: templates/scripts mirrors of integration sources have no sync sensor, and no node --check covers scaffolded .mjs wrappers — add a sync assertion plus a parse lint before shipping new packs**: template duplication and wrapper coverage (from trace 37)
- **diagnostics emitted while a --format json command runs must go to stderr; a single stdout println corrupts the one-JSON-object contract**: verify --bless messages and verdict lines; any CLI path that prints during JSON mode (from trace 36)
- **a ratchet that must hold in CI belongs in a committed file (plans/baselines.json), not only local libSQL; hash its bytes into the policy fingerprint so a bless invalidates stale evidence**: findings ratchets, eval floors, any gate that must be identical across clones and CI (from trace 36)
- **adding a new db repo module requires registering it in schema_usage PROD_SOURCES or the dead-column guard reports its columns as unwritten**: new crates/db/src/repo_*.rs writers (from trace 36)
- **schema bumps in deny_unknown_fields structs add defaulted fields, widen the status acceptance range, extend the chain-seal payload, and update every dogfood version assertion; pre-fingerprint schemas stay legacy**: evidence schema versioning and additive compatibility (from trace 40)
- **an intermittent ETXTBSY ("Text file busy" / os error 26, ErrorKind::ExecutableFileBusy) on exec means a fork/exec race, not a broken script: a forked child holds inherited write-descriptors until its own execve completes, so exec of a just-written file fails while another thread is mid-write — retry via shell::retry_executable_busy and treat a silent fallback as the symptom**: any path that execs a script this process just wrote (write + chmod + spawn): skill walkthroughs, the semantic selector, hook runners; it surfaces as an intermittent test flake (~1/8) or a silently degraded code path (from trace 6)
- **run `do-harness loc` before editing a file that is already near the ceiling, and `do-harness split <file>` when the LOC sensor fires on a file with an extractable #[cfg(test)] module or one oversized top-level item**: feedforward LOC management: `loc --warn` prints total/code/test per file without running the sensor, `split` extracts the module (or the largest item that is itself under the ceiling) and prints the plan first; `split` refuses rather than emitting code it cannot make compile when macro_rules!/include!/non-test cfg shapes are present (from trace 41)
- **a lexical path check plus is_dir()/read_dir() follows symlinks: canonicalize the root and each managed directory and require containment before hashing a tree, and never render entry paths with to_string_lossy because distinct non-UTF-8 names collapse onto one replacement character and make the provenance digest ambiguous**: cross-repo provenance digests, or any code that hashes a manifest-declared directory tree; the same review also showed that accepting an abbreviated commit pin (7 hex) leaves a provenance anchor ambiguous across repositories and time (from trace 1, session skills-drift-hardening)
- **a sensor that parses tool output on stdout can report a phantom finding forever: check the parser against the mode actually used (`cargo llvm-cov nextest --lcov` prints no `TOTAL` table, so the harness parsed nothing and shipped `FINDINGS: 1` on every run until the count was derived from the report's own LH/LF totals)**: any sensor whose verdict is computed from captured command output, especially coverage or benchmark wrappers whose flags change the printed summary (occurred in the coverage sensor, which sat quarantined at `attempt_count=3` because of it)
- **a test that spawns a nested build must strip the launcher's toolchain state: an inherited RUSTC_WRAPPER (cargo-llvm-cov), RUSTFLAGS, CARGO_TARGET_DIR or LLVM_PROFILE_FILE makes the nested `cargo llvm-cov nextest` re-enter the running session and die with `Resource temporarily unavailable (os error 11)`, so sandbox assertions flip only under instrumentation and never under `cargo test` — and instrumented children drop `default_*.profraw` into their working directory**: sandbox/dogfood tests that run cargo or the built binary under a coverage or wrapper session (from PR #185 triage)
- **a toolchain pin file (`rust-toolchain.toml`) silently overrides the toolchain a CI job installs, so a "check on MSRV" step that only runs `cargo check` tests the pinned channel and can never fail — measured here: the job reported PASS while `cargo +1.85 check --workspace --locked` failed with five let-chains in `binary.rs`, `hooks.rs`, and `status/locate.rs`**: select the version explicitly (`RUSTUP_TOOLCHAIN: <msrv>` or `cargo +<msrv>`), prefer `--all-targets` so test code is covered too, and run the suite rather than only a check when the claim is that the package is *verified* on its MSRV — the Cargo Book's `Verified` expectation is "automated testing" on the supported version, which a type check is not; a gate that cannot fail is worse than no gate, because it certifies a false `rust-version` claim (from the MSRV slice)
- **Workload-aware Tokio guidance (template #336)**: keep short bounded CPU (<10-100µs) on async worker threads rather than cargo-culting spawn_blocking offloads; reserve spawn_blocking/pools for genuinely blocking disk/FFI or sustained heavy CPU (>1ms); flag unbounded spawn fan-out, lock-across-.await, and repeatedly-ready loops during review (from .agents/skills/tokio-performance/SKILL.md)
